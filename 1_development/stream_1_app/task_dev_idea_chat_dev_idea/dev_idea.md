# Dev idea — chat label: **dev idea**

## Instant gratification on first app open

As soon as the app exists for a new user, they should get **immediate, visible payoff**, not a long empty onboarding. First-session delight is a design priority.

## NFT loop (keep, sell, or browse)

- **Mint an NFT early** in the journey (onboarding milestone, first wallet connect, or first completed action — exact trigger TBD). This gives a tangible, ownable artifact right away.
- **Keep it** in the wallet as proof of participation / collectible, **or list it for sale** if the user wants liquidity or to trade.
- **NFT marketplace**: a dedicated place in the app to discover, buy, and sell these (and any future) NFTs so the mint is not a dead end.

## Notes for alignment

- Protocol **stablecoin mint/burn** and **xMinima** mechanics are separate from app-level **NFT** minting; any public copy should not blur “mint Stables” with “mint commemorative/trading NFTs.”
- The public knowledge base already describes **Winiwa testnet** commemorative NFTs as **no protocol utility**; if this idea ships as real product scope, define whether app NFTs are purely social/collectible or have scoped in-app utility, and keep that consistent with Council messaging.

## Open questions

- KYC or pseudonymous listings only (fits Stables ethos).
